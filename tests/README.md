# YMGRE 模块测试

模块测试默认随根工程构建：

```bash
cmake -S . -B build
cmake --build build -j
ctest --test-dir build --output-on-failure
```

PC 高级流程（RGB888）：

```bash
cmake -S . -B build -DYMGRE_CAMERA_COLOR_DEPTH=24
```

MCU/低内存基础流程（RGB565）：

```bash
cmake -S . -B build-mcu -DYMGRE_CAMERA_COLOR_DEPTH=16
```

关闭测试：

```bash
cmake -S . -B build -DYMGRE_BUILD_TESTS=OFF
```

## test_render_context

验证：

- 两个相机使用独立 Target 时互不覆盖；
- 两个相机共享 Workspace 时输出一致；
- 相机使用独立 Workspace 时输出一致；
- MCU 风格外部静态 Workspace 输出一致；
- 外部 Target 不需要相机内部分配 framebuffer，并能通过绑定查询接口取得；
- 普通多边形 Context 管线在共享和独立 Workspace 下输出一致；
- Context 管线不修改对象和灯光上的兼容临时状态。

新增图形测试应优先比较 framebuffer 和 Z-buffer，不使用肉眼截图作为唯一判据。

## test_degenerate_geometry

验证重复顶点、零长度边、共线三角形、近零面积多边形和完全位于窗口外的图元不会产生异常像素；同时检查颜色与深度缓存哨兵、深度范围，以及退化输入后的正常图元仍可绘制。

## test_basic_mesh

验证全部基础网格生成器，包括平面、常用立体、圆环、胶囊体和规则多面体：

- 顶点和三角形数量符合分段参数；
- 所有索引都位于顶点范围内；
- 三角形无退化，凸体法线朝向物体外部，圆环内外壁法线方向正确；
- 每个基础网格都设置有效包围球。

## test_resource_material

验证材质与资源从文件到片元的完整链路：

- 材质默认参数、按名查找、UV 重复采样和禁用材质回退；
- 2x2 纹理经过三角形光栅器后能在 framebuffer 中产生对应 texel；
- 24 位 BMP 在存在行补齐时仍能逐像素无损写入并读回；
- 仓库中的坦克材质脚本能解析颜色并加载同目录 BMP；
- 重复材质脚本不会在场景材质表中产生重复项。

## 高级顶点流程验收标准

本节测试针对 PC 高级流程。MCU 只验收原有基础管线和其低内存 Workspace，不把高级顶点缓存、
逐片元光照或法线贴图列为 MCU 必测项。

`demo_advanced_stages` 按先上排从左到右、再下排从左到右逐项增加条件。检查后一格时，除表中“新增变量”外，
三角形坐标、相机、UV、材质和输出尺寸必须保持不变。第一格失败后不得用后续格判断原因。

```bash
./build/demo_advanced_stages
```

| 格 | 新增变量 | 必须满足 | 判定失败 |
|---|---|---|---|
| 1 | 透视校正顶点颜色 | 三个角分别接近各自顶点色，内部连续，无纹理和光照参与 | 黑块、硬分界、X 形条纹 |
| 2 | 白纹理和白环境光 | framebuffer 与第 1 格逐像素一致 | 任意有效片元发生变化或饱和 |
| 3 | 最近邻黑白棋盘 | 方格边界稳定，同一理论 texel 边界始终归属同一列；不产生双线性灰边 | 方格宽度随机变化、黑白跳列、模糊边缘 |
| 4 | 点光源 | 白 texel 上亮度随距离和入射角连续变化；黑 texel 保持黑色；棋盘边界不移动 | 整片进入背光、亮暗反向、边界随光照移动、内部硬线 |
| 5 | 插值顶点法线 | 相比第 4 格只改变光照分布，变化连续且法线归一化 | 三角形内部接缝、法线长度导致的异常亮斑、X 形条纹 |
| 6 | 平坦法线贴图 | 与第 5 格视觉等价；自动比较允许每通道 1 个量化级或一个 RGB565 台阶 | 明显改变受光方向、UV 边界变化、出现贴图接缝 |
| 7 | 扰动法线贴图 | 与第 6 格存在可测光照差异，变化跟随法线贴图；颜色纹理 UV 不变 | 完全无变化、TBN 方向错误、三角形内部翻转 |
| 8 | 混合 `tangentW` | framebuffer 与第 7 格逐像素一致，手性不得在三角形内插值 | 任意内部翻转、X 形或锯齿状硬边 |

法线贴图只改变片元的受光方向，不会移动顶点，也不会改变三角形轮廓、深度、遮挡关系或 UV
边界。因此第 6～8 格应通过三角形内部的亮暗和色彩变化观察效果；如果要求看到真实的凹凸轮廓，
那属于视差映射、置换贴图或增加几何细分的另一条流程，不能用法线贴图本身验收。

为避免棋盘纹理和三角形轮廓干扰，使用 `demo_advanced_normal_map_detail` 做后续专项验证：
左、中、右三块平面依次为平坦法线、强扰动法线、强扰动法线加混合 `tangentW`。中间平面应出现
明显的块状受光变化，右侧平面应与中间平面一致且不得出现 X 形接缝。

专项 Demo 的验收标准固定如下：

| 图 | 输入 | 预期 |
|---|---|---|
| 1 | 平坦 `(0,0,1)` 法线贴图 | 受光连续，作为法线贴图基准 |
| 2 | 4×4 块状扰动法线，UV 单次覆盖 `0..1` | 平面内部出现稳定、可重复的亮暗块，不出现孤立跳点 |
| 3 | 与图 2 完全相同的法线贴图，顶点 `tangentW` 混合正负 | 与图 2 逐像素等价；出现差异、X 条纹或局部翻转即失败 |

法线贴图源图为 `16×16` texel，每 `4×4` texel 共用一个法线，即画面上是 `4×4` 个方向块，
不是黑白颜色棋盘。图 2 和图 3 看起来相同是设计目标，用于证明 `tangentW` 没有被当作普通
浮点属性在三角形内部插值。

`demo_advanced_normal_map` 是完整流程的左右对照：屏幕左侧为普通平面，屏幕右侧为圆形扰动法线贴图平面。
由于相机屏幕 X 轴与世界 X 轴相反，Demo 内部使用世界 `x=+78` 放置左侧平面、`x=-78` 放置右侧平面。

### 点光源数值标准

第 4 格不能仅凭“比环境光暗”判错。白材质、白 texel 和白顶点色的基准片元应按以下值核对：

```text
L = lightPosition - fragmentPosition
distanceAttenuation = strength / (kc0 + kc1 * |L| + kc2 * |L|^2)
diffuse = distanceAttenuation * max(dot(normalize(N), normalize(L)), 0)
output = texture * vertexColor * materialDiffuse * lightColor * diffuse
```

- `dot(N,L) > 0` 时必须进入正面漫反射，不能使用 `shadowK`；
- 距离更近且入射角更正的白 texel，亮度必须高于远处白 texel；
- 改变 `strength` 时，未饱和片元应近似同比变化；
- 数值测试先使用纯白顶点色和纯白纹理，确认点光公式后再叠加棋盘和顶点颜色；
- RGB24 中间结果允许每通道误差 2，RGB565 framebuffer 按各通道一个量化台阶比较。

如果纯白基准符合公式，而组合画面整体偏暗，这是点光衰减、入射角、顶点色和纹理连续相乘的结果，
应调整 Demo 灯光参数；如果纯白基准也明显偏暗，则属于光照实现或坐标空间错误。

`demo_advanced_point_light` 将点光源相关条件拆成两排六格，编号顺序为先上排从左到右，
再下排从左到右。六格使用相同的大三角形、相机和输出尺寸：

```bash
./build/demo_advanced_point_light
```

| 格 | 唯一新增或改变的条件 | 观察标准 |
|---|---|---|
| 1 | 白顶点色、白纹理、白环境光 | 整个三角形为纯白，作为颜色乘法基准 |
| 2 | 换为正对三角形中心的点光源，关闭距离衰减 | 中心最亮，亮度只随入射角连续变化，不得出现内部硬线 |
| 3 | 点光源移动到世界坐标左上方，仍关闭距离衰减 | 由于当前相机的屏幕 X 轴与世界 X 轴相反，亮区应连续移向屏幕右上方，左下方应更暗 |
| 4 | 保持第 3 格灯位，启用一次距离衰减 | 亮暗方向不变，整体与远端进一步变暗，不得改变几何或边界 |
| 5 | 加入最近邻黑白棋盘纹理 | 白格保留第 4 格光照，黑格保持纯黑，棋盘边界稳定清晰 |
| 6 | 加入 RGB 顶点颜色 | 棋盘黑格仍为黑，白格同时呈现连续顶点色和点光渐变 |

### 屏幕方向与世界方向

本 Demo 的相机朝世界 `+Z`，并按 `viewU = viewN × up` 计算屏幕右向量，因此
`viewU=(-1,0,0)`：世界 `x<0` 会显示在屏幕右侧，世界 `x>0` 会显示在屏幕左侧；
世界 `y>0` 仍显示在屏幕上方。点光源代码中的 `(-45,65,150)` 和
`(-110,80,65)` 因此看起来位于屏幕右上方，这是坐标系约定导致的正常结果，不是光照方向翻转。

### 后续几何标准

完成 1 至 8 格后，继续按以下顺序验证：

1. 镜像 UV：两个同几何三角形只镜像 U；每个三角形内部手性恒定，法线贴图方向整体镜像，不得局部翻转。
2. 透视方形：使用两个三角形组成大角度倾斜方形；棋盘跨对角线连续，对角线两侧不得出现 UV 或亮度接缝。
3. 高级属性裁剪：三角形分别穿过近、远、左、右、上、下裁剪面；新顶点的颜色、UV、法线和切线连续，所有写入坐标和深度均在缓存范围内。
4. 深度重叠：前后两个方形交换提交顺序后 framebuffer 相同；被遮挡片元不得覆盖前景。
5. 多面网格：最后使用立方体检查共享顶点、每面 UV、切线生成和硬边；不得用球体作为首个多面验证模型。

自动化测试至少覆盖第 2 格恒等、第 3 格边界列稳定、第 6 格平坦法线贴图容差、
第 8 格 framebuffer 恒等、镜像 UV 手性、裁剪后属性有限值以及提交顺序无关的深度结果。

当前裁剪核心函数使用 `test_advanced_clipping` 验收：一个顶点穿过近裁剪面，另外两个顶点
位于视锥内部。测试要求输出多边形仍至少有 3 个顶点，所有新顶点位置在六个视锥平面内，
且 UV、颜色、法线和切线均为有限值。该测试验证裁剪数学本身；高级管线接入后再增加画面级 Demo。

画面检查使用 `demo_advanced_clipping`：一个顶点位于近裁剪面之前，裁剪后应显示为保留
顶点颜色渐变的四边形，不应出现黑洞、越界写入或颜色断裂。

六面裁剪画面使用 `demo_advanced_clipping_planes`，按先上排、再下排的顺序依次为近、远、
左、右、上、下裁剪面。每格都通过真实 `wN` 高级管线，三角形越过对应平面后仍应显示
连续 RGB 渐变；不得整面消失、越过视口边界、出现黑边或在新生成顶点处发生颜色断裂。

深度画面检查使用 `demo_advanced_depth`：左右两图分别交换前后平面的提交顺序，红色前景
平面应始终遮挡蓝色后景平面，两图应视觉一致；若顺序改变可见结果，则深度测试失败。

多面画面检查使用 `demo_advanced_cube`：应同时看到立方体的多个面，面与面之间保持清晰
硬边，不能出现共享顶点裂缝、法线跨面平滑或局部 X 条纹。

高级管线现在尊重对象的 `renderMode`：`GRE_RenderMode_Face` 对每个三角形使用面法线，
`GRE_RenderMode_Vertex/Pixel` 才使用顶点法线插值。立方体等硬表面必须显式使用 Face 模式；
如果在 Face 模式仍出现同一平面对角线亮度差异，才判定为管线错误。
`YMGRE_Object_EnableVertexAttributes` 和 `YMGRE_Object_GenerateVertexAttributes` 只负责顶点属性的
分配与生成，不得修改已选定的 `renderMode`；高级 Demo 必须显式选择 Face、Vertex 或 Pixel。

模式画面检查使用 `demo_advanced_render_modes`：左、中、右分别为 Face 硬边立方体、Vertex
共享顶点法线立方体、Pixel 法线贴图平面（16×16 法线图，每 4×4 texel 一个方向块）。Face 应保持硬边，Vertex 暴露共享顶点平滑结果，
Pixel 应显示片元法线贴图细节；三格若出现完全相同，说明模式分派仍未生效。

模式 Demo 的固定验收标准：

| 图 | 模式和输入 | 必须观察到 | 失败判据 |
|---|---|---|---|
| 1 | `GRE_RenderMode_Face`，立方体逐面法线 | 同一平面两个三角形亮度一致，面与面之间有硬边 | 平面内出现对角线接缝，或相邻面被错误平滑 |
| 2 | `GRE_RenderMode_Vertex`，立方体共享顶点法线 | 共享角点处法线连续，允许跨面平滑 | 法线不插值、出现非法亮斑或随机断层 |
| 3 | `GRE_RenderMode_Pixel`，平面 + 16×16 法线图 | 画面出现 4×4 大块受光变化，每块由 4×4 texel 共用一个方向 | 没有法线细节、出现 X 条纹、块边界随机跳变 |

图 2 和图 3 的输入本来不同，不能要求两图逐像素一致；应分别按各自模式的目标验收。

三种模式现在使用独立计算路径：Face 从 `polygon->pN` 读取面法线并逐片元应用同一法线；
Vertex 在投影和裁剪前计算每个顶点的 `vertexLighting`，裁剪点插值该缓存，光栅阶段只插值
光照颜色；Pixel 则在每个片元插值法线并重新计算光照。`test_advanced_rasterization`
同时验证 Vertex 专用光栅器确实读取缓存光照，而不是回退到 Pixel 路径。

高级光照画面检查使用 `demo_advanced_lighting`：第 1 图为只有全局光的漫反射基准，第 2 图加入位于物体正面的暖色点光
和高光，第 3 图加入红/蓝双点光源，第 4 图为明亮冷色环境光。高光应集中在受光面并随光源颜色变化，双光源结果不能
覆盖溢出成白块，也不能出现光照接缝或负值反转。若第 1 图同一平面沿三角形对角线出现亮度条纹，
必须记录为失败：这通常暴露共享顶点法线被跨面平均的问题，不能在 Demo 中强制法线来掩盖。

高光专项使用 `demo_advanced_specular`：第 1 图关闭 `mirrorKs`，只显示环境光和漫反射；
第 2 图保持相同几何、材质和灯位，仅把 `mirrorKs` 提高到 `0.85`；第 3 图保持高光参数，
只移动点光源。第 2 图必须比第 1 图多出局部高光，第 3 图高光中心必须跟随灯位移动；
整面变白、高光不移动、跨三角形断裂或出现 X 条纹均判定失败。

聚光灯专项使用 `demo_advanced_spot_light`：第 1 图是与后续两图同灯位、同衰减的点光基准；
第 2 图只改为正对平面的聚光灯，应显示居中的内锥亮区和连续衰减的外锥边缘；第 3 图只改变
聚光方向，亮区应移向屏幕左上方。聚光边界不得出现硬切黑环、三角形对角线、锥外漏光或方向反转。

材质通道专项使用 `demo_advanced_material_channels`：第 1 图只保留红色 `ambient`，应为均匀红色平面；
第 2 图只保留绿色 `diffuse`，应为连续的绿色点光渐变；第 3 图把 `ambient` 和 `diffuse` 置零，
只保留蓝色 `specular`，应只显示局部蓝色高光。任一图出现其它材质通道的颜色、第 3 图高光变白或
完全消失，都说明材质通道未真正分离。旧 `YMGRE_PolygonLighting_Color` 仍使用白色镜面材质保持兼容，
高级 Face/Vertex/Pixel 路径使用 `YMGRE_PolygonLighting_ComponentsAdvanced` 传入材质的
`specular`，并分别返回基础光照与镜面光照。

纹理与高光合成使用 `demo_advanced_specular_texture`：三图使用完全相同的 4×4 黑白棋盘和点光；
第 1 图关闭高光，中心黑格必须保持黑色；第 2 图开启白色镜面高光，高光必须连续跨过黑白格；
第 3 图只把镜面色改为蓝色，棋盘的漫反射不变，高光应变蓝。高级合成顺序固定为
`texture * vertexColor * (ambient + diffuse) + specular`；黑色 texel 或黑色顶点色不得消除镜面高光。

高光粗糙度使用 `demo_advanced_gloss`：三图除了高级材质的 `specularPower` 分别为
`8`、`30`、`96` 外完全相同。三图的高光中心位置和峰值应基本一致，但亮区宽度必须从左到右
明显收窄；如果三图宽度一致，说明材质参数未进入光照计算。`specularPower=0` 固定回退到 `30`，
以保持现有材质和只有法线贴图的高级材质兼容。

聚光镜面使用 `demo_advanced_spot_specular`：第 1 图关闭 `mirrorKs` 作为纯聚光漫反射基准；
第 2 图只开启镜面项，锥内中心应新增局部蓝色高光；第 3 图保持聚光正对平面，只平移灯位，
聚光漫反射与镜面高光应一起移向屏幕左上方。镜面项不得泄漏到外锥之外，也不得在三角形对角线上断裂。
只旋转固定位置的聚光灯时，锥形区域会移动，但 Blinn-Phong 镜面中心仍由光源位置、片元位置和视向量决定；
不得把“镜面中心不跟随纯方向旋转”误判为引擎错误。
Demo 还会把相机关于平面镜像，用“光源到镜像相机”的连线与平面求交，得到理论镜面点；
投影到屏幕后，与 framebuffer 中蓝色镜面分量的峰值坐标比较。峰值允许 RGB888 量化造成的 2 级平台，
平台内取距理论点最近的像素；两坐标距离不得超过 3 像素，
运行时会直接打印 `expected`、`framebuffer peak`、`delta` 和 `PASS/FAIL`。

多光源累加使用 `demo_advanced_light_accumulation`：第 1 图只有红色点光，第 2 图只有蓝色点光，

颜色为红蓝累加结果。Demo 对所有写入深度的像素执行

# 光线追踪验收标准

`test_ray_tracing` 必须同时通过三角形求交、单物体求交、场景最近交点、相机像素射线、反射向量和折射向量测试。
`demo_advanced_raytrace` 只验证相机射线到三角形的可见性与重心颜色插值；命中边界应连续，背景不得出现误命中。
`demo_advanced_raytrace_object` 只放置一个六面异色立方体，从斜上方发射相机射线；命中像素必须超过 10000，
且至少三个立方体面各自命中 100 个以上像素。公共边上的少量归属不计为有效可见面。
`demo_advanced_raytrace_objects` 放置左右错开的红、蓝两个立方体；两个物体必须分别命中超过 3000 个像素，
并由场景最近交点决定遮挡关系。
`demo_advanced_raytrace_materials` 验证多物体颜色区分、镜面反射递归以及玻璃球的入射/出射折射；镜面和玻璃效果必须来自二次射线，不能用预先绘制的贴图伪造。
