# 开发板移植优化回合并（2026-10-05）

本次以库提交 `eb90267` 为基线，审阅 AT-SURF-F437 移植工程的 YMGRE 副本及用户提供的《YMGRE 开发板移植记录》，将可独立适配的通用改动回合并到新版库。移植副本没有新版全部 PBR、透明度 Mipmap、线性色彩和并行光栅功能，因此没有整目录覆盖。

## 已合入

| 改动 | 适用范围与兼容约束 |
| --- | --- |
| 跨平台头文件清理 | 只保留完整的 `YMGRE_PubType.h`，删除仅大小写不同的旧 `YMGRE_Pubtype.h`，避免 Windows 解压/检出冲突；MSVC pragma 由 `_MSC_VER` 保护，四个无参声明明确为 `(void)`。 |
| 连续清屏 | 背景色转换一次，深度和颜色分别顺序写入；同时支持相机自有 Target 和外部 Target，RGB565/RGB888 使用同一实现。 |
| 六平面裁剪快速判断 | 每个平面只计算一次各顶点距离；全在内直接跳过属性复制，全在外直接返回，跨平面仍执行完整属性插值。 |
| 包围体提前剔除 | 高级材质管线及延后线框路径先判断对象包围体，再做对象全部顶点的相机空间变换。 |
| 光照准备复用 | 每个光源的材质响应和聚光方向每批顶点准备一次，逐顶点的灯光累加顺序保持不变。 |
| 共享顶点光照 | 单面、非 unlit、无 lightmap 的顶点着色对象可在 Workspace 中一次计算全部顶点。可见三角形太少、顶点超过 65535 或需要逐面翻转法线时保留逐三角形路径。不修改共享源网格。 |
| 整数高光幂 | Blinn–Phong 的整数指数改用平方求幂；数学表达式相同，但浮点运算顺序不同，不承诺所有输入逐位一致。PBR 和光追公式保持原实现。 |
| 浮点线框 | 新增 `YMGRE_Img_LineDepthFloat`；高级网格线框保留浮点端点，规范化遍历方向，使用透视深度。旧整数 API 保留；原有物体叠线显示背面边的语义保留；点状投影也按深度规范化端点顺序。 |
| 高级材质初始化 | 回归发现旧法线/高光 Demo 和测试直接分配扩展材质，未初始化新增的透明度/PBR 字段；统一改用现有 `YMGRE_Material_EnsureAdvanced`。 |
| 可见顶点与投影缓存 | 背面判断同时标记被可见面引用的顶点；高级材质管线只变换这些顶点，逐顶点计算六平面裁剪码，完整位于视锥内的三角形复用一次投影结果。双面材质和线框保持全顶点处理；裁剪边界继续使用属性插值。动态 Workspace 按最大网格扩容，固定 Workspace 可通过 `YMGRE_RenderWorkspace_BindProjectionCache` 绑定调用者提供的缓存，未绑定时退回原路径。 |
| 矩阵快速路径 | 对确认为仿射对角矩阵的相机变换直接缩放平移；其余矩阵仍做完整乘法。法线和切线保持高级材质所需数据，避免破坏 PBR 与法线贴图。 |
| 光栅专用路径 | RGB565 默认启用顶点光照插值优化和适用平面基向量的预处理着色；恒定深度场景可使用采样细分的近似光照曲线。深度接近共面时先重新精确计算再判断遮挡。RGB888 默认保留原精确片元路径；带透明贴图、线性颜色、PBR、聚光灯、烘焙光照等不满足条件的情况自动走原路径。 |
| 连续索引池 | `YMGRE_Object_CompactTopology` 可在准备阶段合并对象拥有的多边形索引；编译选项 `YMGRE_COMPACT_OWNED_TOPOLOGY=ON` 可在属性生成时自动执行。调用方必须保证这些索引来自库的索引分配器、归对象所有。 |
| 快慢内存策略 | 热渲染缓存、投影缓存和帧缓冲固定优先调用 `GRE_malloc0`，不足时回退 `GRE_malloc1`；分配头记录匹配的释放器。图像和几何数据固定使用 `GRE_malloc1`。无需构建开关；板级适配分别实现快、慢内存分配器。独立颜色缓存仍可通过 `YMGRE_RENDER_COLOR_MALLOC/FREE` 提供。 |

`gre_render_workspace` 和 `gre_object4d` 为投影缓存与连续索引池扩展了字段，**本次必须同时更新静态库和头文件并重新编译应用**。RGB565/RGB888、16/32 位索引和材质功能裁剪继续支持。浮点线框消除端点整数截断造成的偏移，但不是抗锯齿；次轴取最近像素仍可能有半像素量化误差。

## 本次主机验证

- 四种 Release 组合：RGB565/RGB888 × index16/index32，每种 CTest 23/23 通过；RGB565 启用专用光栅路径。另以完整 RGB888 和启用索引整理的最小 RGB565 配置运行 ASan/UBSan，各 23/23 通过。固定快慢内存分层后，以上六种配置重新构建并复测，仍各 23/23 通过。
- 独立分配器替身检查了快内存成功、快内存耗尽回退慢内存、按来源释放、图像与几何数据走慢内存以及超大尺寸拒绝；ASan/UBSan 通过。四种预编译 SDK 变体重建成功，独立消费者验证及 15 项 SDK 配置检查通过。
- 新增 `test_portable_optimizations`：512 组奇数尺寸与外部目标清屏；0～255 高光指数的数值误差检查；6000 组裁剪、容量边界和原地输入输出检查；600 组浮点边的方向对称、半像素距离、透视深度与叠线检查；批量/单点光照一致性；24 个相机/材质/裁剪组合下，共享顶点路径与强制逐三角形路径的颜色和深度一致，源网格及光源不被修改。
- GCC AddressSanitizer + UndefinedBehaviorSanitizer 使用 `ASAN_OPTIONS=detect_leaks=0`；当前环境未验收 LeakSanitizer。
- 11 个直接创建扩展材质的法线/高光 Demo：改用初始化接口后，RGB888/index32 完整功能的 ASan/UBSan 无窗口运行全部通过。
- 另将基线裁剪函数与新函数编入同一差分程序：6000 个随机三角形、所有输出容量下，顶点数量、顺序及全部属性逐字段逐字节一致。
- Girl 查看器使用 SDL dummy、4 个线程：串行/并行一致、恢复线性色彩状态、反转提交顺序、近面裁剪检查通过；RGB888 的 5 张 PPM 与 `eb90267` 基线逐字节一致。
- 同机同一 RGB565/index32 合成球体（534 顶点、1064 三角形、160×240，7 次采样中位数）相对于合入前基线：单帧约 498→256 µs，可见渲染快约 49%；清屏约 21.5→10.6 µs，532 顶点/4 光源批光照约 148→98 µs。该基准不能外推到其他场景或开发板帧率。
- 固定内存分层前后使用同机同场景配对测量，各运行 3 轮、每轮 7 次采样：球体帧时间中位数约 259→256 µs。主机的 `GRE_malloc0`、`GRE_malloc1` 均使用系统 `malloc`；这次未观察到帧时间变慢，但分配头和首次分配增加了少量内存与分配工作，其他平台仍需上板测量。
- 该 RGB565 场景与关闭快速插值/光照曲线的同版精确路径对比：38,400 像素中 1,116 个颜色值不同（2.9%），每个 RGB565 通道最大相差 1 个量化级。快速光栅是可关闭的画质/性能取舍，不保证逐像素一致。

主机测试不代表板端时序验收。本次没有连接 AT-SURF-F437，没有重新执行 ARMCC 编译、烧录、DMA 联调和板端测速。移植记录中的地球 18.630～18.684 ms 更新加渲染、约 24.3～24.4 FPS 是移植工程特定场景的历史结果，不能作为本次新版库性能承诺。

复现常规检查：

```sh
cmake -S . -B build/.cache/portable-check \
  -DCMAKE_BUILD_TYPE=Release \
  -DYMGRE_BUILD_DEMOS=OFF -DYMGRE_BUILD_YMGUI_HOST=OFF \
  -DYMGRE_CAMERA_COLOR_DEPTH=16 -DYMGRE_INDEX_BITS=16 \
  -DYMGRE_ENABLE_PNG=ON -DYMGRE_ENABLE_JPEG=ON
cmake --build build/.cache/portable-check -j4
ctest --test-dir build/.cache/portable-check --output-on-failure
```

分别改为色深 `24`、索引 `32` 可覆盖其余组合。`./sdk/build.sh --jobs 4` 重新生成四份静态库、配套头文件及独立消费者验证结果，输出到 `build/YMGRE_libs`。

## 本次未带入

- ARMCC 汇编/DSP、SDRAM 地址、DMA 同步限制和板级计时：留在目标平台适配层。
- 移植版借用切线字段存放投影坐标的具体写法没有照搬；新版 PBR 与法线贴图需要切线，库以独立投影缓存实现同样的共享顶点复用。
- 当次没有增加模型层级选择、颜色纹理 Mipmap 或资源流式加载；后续已新增按材质显式生成的颜色纹理 Mip，以及[模型／图片 LOD 层级选择和描述文件](lod.md)。自动网格简化与资源流式加载仍未加入。
