# 模型与图片 LOD

LOD 用来为同一个物体选择不同精细程度的资源：物体在屏幕上看起来大时用精细模型，看起来小时用简化模型，也可以选择图片替身来降低绘制开销。

**图片替身是可选项。所有层级都可以使用三维模型。** GRE 的 LOD 模块负责层级选择，也提供一次性网格简化；资源加载和具体绘制由应用负责。

## 全部使用模型：近、中、远三级

例如，提前准备精细、简化和粗略三份模型，分别绑定到下面的资源名：

```text
YMGRE_LOD 1
hysteresis 0.10
level mesh 120 detailed
level mesh 40 simplified
level mesh 0 coarse
```

每条 `level` 的格式为：

```text
level <mesh 或 image> <该层级的最低像素阈值> <资源名>
```

这里的数值是**物体包围球投影到屏幕上的直径，单位为像素**，不是与相机的距离，也不是模型的三角形数量。它是估算的屏幕尺寸，不是对实际可见像素逐个计数。物体尺寸、实例缩放、相机远近、视角和画面分辨率都会影响这个数值。

首次选择时，从第一层向后查找，使用第一个满足“投影直径大于或等于阈值”的层级：

| 屏幕投影直径 `p` | 选择的资源 | 预期用途 |
| --- | --- | --- |
| `p >= 120` | `detailed` | 近处，精细模型 |
| `40 <= p < 120` | `simplified` | 中距离，简化模型 |
| `0 <= p < 40` | `coarse` | 远处，粗略模型 |

所以，**首次选择时恰好 120 像素也会使用 `detailed`，恰好 40 像素会使用 `simplified`**。阈值必须从高到低严格递减，最后一层必须是 0，表示最小尺寸也有可用资源；0 不表示停止绘制。上述 120、40 是示例值，应按资源和画面效果调整。

三份资源始终是三维模型，只是三角形数量和细节不同。它们应使用一致的原点、朝向和尺寸基准，应用在切换时保持同一实例的世界变换，并使用统一的包围球进行层级判断，避免切换资源本身改变判断尺寸。简化模型可以手工制作，也可以通过 `YMGRE_LOD_SimplifyMesh` 从原模型一次性生成。

## 后续切换：为什么不是一过 120 就换

`hysteresis` 表示切换缓冲比例，用来避免物体尺寸在边界附近波动时反复切换。**首次选择使用上面的原始阈值；实例已有层级后，切换还要考虑上一层级。**

设置 `hysteresis 0.10` 后：

| 切换方向 | 实际切换条件 |
| --- | --- |
| 精细模型 → 简化模型 | `p < 108`，即 `120 × 0.90` |
| 简化模型 → 精细模型 | `p >= 132`，即 `120 × 1.10` |
| 简化模型 → 粗略模型 | `p < 36`，即 `40 × 0.90` |
| 粗略模型 → 简化模型 | `p >= 44`，即 `40 × 1.10` |

例如，正在显示精细模型时，尺寸从 125 降到 115 像素仍保留精细模型，要低于 108 才降级；正在显示简化模型时，尺寸回到 125 也不会马上升级，要达到 132 才升回精细模型。缓冲区内保留当前层级是预期行为。

`hysteresis 0` 表示不留缓冲，后续选择也直接按 120、40 切换。尺寸一次跨过多个边界时，可以直接跨越多个层级。

## 可选的图片替身

如果希望在远处改用图片，可以把最后一级设为 `image`。自然场景 demo 的 [grass.lod](../project_Demo/nature_preview/assets/grass.lod) 就是两级方案：

```text
YMGRE_LOD 1
hysteresis 0.10
level mesh 90 original
level image 0 baked8
```

它在近处使用原始草模型，远处使用图片替身。图片仍需要绘制并处理透明区域和深度遮挡，但省去了完整草模型的大量三角形处理。这里的“八方向图片”是同一资源的八个观看方向，**不是八级 LOD**。

这个 demo 在启动时从草模型烘焙图片，再按观看方向选图。图片烘焙和绘制目前位于 demo 的 `grass_impostor` 实现中，通用图片烘焙尚未加入库。

LOD 接口支持前面的全模型方案，但当前草地 demo 只绑定 `original` 和 `baked8`，并缓存已创建的模型实例。把它改成三级模型还需要加载和绑定三份模型、在模型层级改变时更新实例网格，以及解除包围球计算对图片烘焙数据的依赖，不能只修改 `.lod` 文件。

## 在应用中接入

`YMGRE_LOD_Object` 保存从精到粗的资源层级，同种物体的多个实例可以共享它。`YMGRE_LOD_Instance` 为每个实例保存当前层级和是否已初始化，用于各自的切换缓冲；首次使用前应将实例状态清零。

层级可由 `YMGRE_LOD_Init` / `YMGRE_LOD_Add` 在代码中建立，也可用 `YMGRE_LOD_Parse` 解析文本描述。与前面三级模型配置对应的代码如下，其中三个模型资源可由应用导入或通过库的简化接口准备：

```c
YMGRE_LOD_Object tree;
YMGRE_LOD_Init(&tree, 0.10f);
YMGRE_LOD_Add(&tree, YMGRE_LOD_MESH, 120, "detailed", detailed_mesh);
YMGRE_LOD_Add(&tree, YMGRE_LOD_MESH, 40, "simplified", simplified_mesh);
YMGRE_LOD_Add(&tree, YMGRE_LOD_MESH, 0, "coarse", coarse_mesh);
```

应用应检查初始化后各次 `YMGRE_LOD_Add` 的返回值。每帧调用 `YMGRE_LOD_SelectCamera` 时，传入相机、实例状态，以及物体包围球的世界坐标中心和已经计入实例缩放的半径。函数估算投影直径并返回选中的层级；应用随后根据其 `kind` 和 `resource` 绘制，层级变化时同步更新缓存的绘制资源。函数不会自动替应用替换网格或提交绘制。如果应用已计算好投影直径，也可以直接调用 `YMGRE_LOD_Select`。

文本中的资源名是单个无空格标识，最长 127 字节；应用可以把它解释为文件路径或资源键。`detailed` 等名字只是示例资源键，不代表 GRE 内置文件格式或自动加载规则。解析器不读文件，也不加载资源；应用读取文本后，通过 `YMGRE_LOD_Resolve` 回调把资源名绑定为已有模型或图片。解析和绑定失败均不会留下半更新对象。对象和层级不拥有这些资源，释放仍由应用负责。

## 一次性网格简化

`YMGRE_LOD_SimplifyMesh` 从三角网格生成独立模型，不修改原模型。传入目标三角形比例、最大相对几何误差和是否允许删除独立薄片部件；返回实际面数、折边数与删减部件的面数。生成结果可以直接加入 LOD，并由应用保存或在不再使用时调用 `YMGRE_Free_Object` 释放。

连续网格采用二次误差度量（QEM）选边折叠。开边界可沿自身边线受约束地折叠，避免薄片网格只能整块删除；算法同时检查面朝向和连接关系。`prune_components` 现在只允许完整删除不超过 16 个三角形的小连通块，较大的草片和成对正反面必须通过折边减面，避免一次消失大片轮廓。本机示例草网格原有两对约 93／98 面的表面，现可得到逐级递减的面数。`max_relative_error` 只约束折边，**不约束完整小部件删除**；要求严格几何误差上限时应关闭后者。材质子网格分别处理，UV、导入法线和顶点颜色随结果复制或插值。带逐面光照贴图的对象不支持简化；几何保护也可能使实际面数高于目标。

[全模型 LOD 示例](../project_Demo/lod_mesh_preview/README.md)对草、树和球面分别生成原模型／中级／远级并排图。通用图片烘焙仍留待后续。
