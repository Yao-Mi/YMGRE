# 原生漫游移植经验回合并（2026-10-08）

来源是 `ymgre_roam_perf320` 的有效源码和截至 2026-10-08 的构建、性能、图像差分记录。回合并以当前 YMGRE 为基线，保留透明度、PBR、线性色彩和并行 PBR 调度；没有整包替换旧光栅、导入资源、烧录日志或实验备份。

## 已接入的能力

- `GRE_CompactMesh` / `YMGRE_Camera_AppendMeshInstance_wN`：借用不可变位置、UV、法线、面法线和索引，按实例绘制，复用小顶点缓存或调用者提供的完整缓存，延迟读取属性和求光照。位置共享与完整顶点去重按浮点字节比较，保持 UV 缝、法线和面顺序。
- 初始化期 `PrepareBounds`、`PrepareFaceCenters`、`ValidateIndices`、`PrepareIndexed`、`PrepareSharedPositions`。可选保守 AABB 剔除由 `camera->meshBoundsEnabled` 控制；默认关闭。面簇准备接口为资源组织提供能力，不默认启用或承诺其性能。
- `YMGRE_RenderWorkspace_ReserveFaceOrder`：拥有工作区的稳定八桶排序缓冲，可预分配并重复使用，扩容失败保留原缓冲。`YMGRE_OPAQUE_FACE_BUCKETS` 默认关闭；不足容量时保留原面顺序。排序适用于不透明面，不能替代透明场景排序。
- `YMGRE_Camera_AppendOpaqueBatch_wN`：往已初始化的同一目标追加不透明物体，保留颜色和深度，便于复用有限大小的物体工作区。按实际相机状态拒绝线性色彩，不因编译支持线性色彩而拒绝普通相机。
- 相机按行背景回调：`backgroundRow(row,height,user)` 返回这一行的最终 framebuffer 颜色，避免绘制后再扫描全屏补背景。上下文借用；默认 NULL。该回调用于普通颜色目标，不生成 HDR 线性背景。
- 可配置热工作区、framebuffer、投影缓存、模型和纹理的快/慢内存偏好；保留当前默认值、`long double` 对齐、快内存失败回退和对应释放函数。自定义颜色分配器必须同时提供匹配的释放函数，失败仍回退常规目标分配器。
- ARMCC 枚举、失败清理作用域兼容修整及硬件单精度平方根。`YMGRE_FAILURE_HALT=ON` 可显式选择裸机日志后本地停止；默认保留主机退出行为，不按编译器猜测运行平台。
- `YMGRE_PROFILE_RENDER_STAGES=ON` 的串行阶段计数，支持调用者时钟；默认关闭，关闭时没有时钟调用。槽 0/1/2/3/5/6 为清屏/变换/剔除/顶点光照/顶点光栅/高级批管线。范围存在嵌套，不可相加推算全帧。DWT 初始化属于板级端口，计数、复位和时钟配置不能与并发绘制同时进行。

## 阶段计时默认关闭

正常使用无需调用计时接口，也无需额外设置关闭开关。CMake 的 `YMGRE_PROFILE_RENDER_STAGES` 默认是 `OFF`；直接编译源码且未定义该宏时，头文件默认值为 `0`。

关闭时，渲染函数中的计时包装不参与编译，不会在每帧读取时钟或累计阶段耗时。接口保留在源码中供性能排查使用，接口存在不表示计时已启用。

需要排查性能时，才主动设置 `-DYMGRE_PROFILE_RENDER_STAGES=ON` 并重新编译。若复用曾经开启计时的 CMake 构建目录，缓存会保留 `ON`，应显式设置 `-DYMGRE_PROFILE_RENDER_STAGES=OFF` 并重编译；直接编译源码则设为 `0`。库与调用方的配置须一致。

下文的验证命令主动开启计时，是为了覆盖该可选功能，不是日常构建的默认配置。DWT 的启动仍由板级端口负责。

## 实例绘制契约

1. 使用初始化函数创建缓存；默认缓存约几十 KiB，适合预先放在堆或静态存储，不应反复放到很小的 MCU 栈。完整缓存、共享位置、模型暂存区和网格元数据均由调用者持有、释放，库不取得所有权。
2. 传入有限、正确的不可变几何，法线与面法线必须匹配网格。模型矩阵须为正均匀缩放与旋转、平移的组合；不支持剪切、非均匀缩放、反射或投影变换。绘制入口检查矩阵和索引，拒绝不支持的输入时返回 0。
3. 只支持实体、不透明、单面、顶点光照材质。双面、无光照、法线贴图、启用的 PBR 或线性色彩返回 0，由应用提交给现有高级物体管线。此接口没有 UV1、切线、镜面系数和烘焙光照载荷，不能用它替换这些模式。
4. 在初始化阶段调用 `YMGRE_RenderWorkspace_Reserve(ws,0,0,lightCount)`。实例接口不在帧内扩容，灯光容量不足时返回 0。传统追加批接口仍沿用既有工作区扩容规则，应用须先按最大物体和灯数预留容量。
5. `YMGRE_PREVALIDATED_INDICES` 默认关闭。启用时仅信任显式 `ValidateIndices` 后设置的 `mesh.indicesValidated`；索引或计数修改后必须清除标记并重新验证。外部排序、预处理输出和输入不能随意重叠。
6. 完整顶点缓存每次实例绘制失效，以代次标志延迟清除；代次回绕会完整清除状态。不跨实例/帧保留旧光照或变换结果。

## 内存选项

| CMake / 编译定义 | 默认 | 作用 |
|---|---:|---|
| `YMGRE_RENDER_PREFER_FAST_MEMORY` | 1 | 热工作区快内存优先 |
| `YMGRE_RENDER_FAST_TARGET` | 1 | 目标颜色和深度随快内存策略；设 0 可留给外存 |
| `YMGRE_PROJECTION_PREFER_FAST_MEMORY` | 1 | 投影位置快内存优先；裁剪码保持热工作区策略 |
| `YMGRE_GEOMETRY_PREFER_FAST_MEMORY` | 0 | 模型可选快内存 |
| `YMGRE_IMAGE_PREFER_FAST_MEMORY` | 0 | 图像可选快内存 |

所有库与调用方必须使用一致的分配策略、色深、索引位宽和功能宏。公共相机、工作区和新增缓存布局有变化，应用须完整重新编译；不可把新头文件配到旧静态库。SDK 打包与 CMake 导入同步记录这些配置并拒绝不一致配置。已有发布包没有被覆盖，需要发布新版时重新打包。

## 保留在端口或暂未移入的内容

- SRAM 容量切换、SDRAM 地址、LCD DMA、DWT 启动、Keil 编译器/调试器配置属于板级工程。主库不设置芯片选项字节。
- 深度行缓存需要包括 PBR、线框、直接像素、目标切换在内的完整一致性协议，当前库继续使用统一原始深度缓冲。小 Mip/打包 RGB 缓存增加常驻内存，共享颜色查表需要并发访问设计，未直接带入。
- 扩大快速光栅条件、改变深度表达式、整数 UV 边界检查可能改变边界像素。保留当前光栅及其既有精确回退规则；实例端也移除了依赖端口覆盖规则的小像素预剔除。
- 无收益或已撤回的扫描行暂存、MPU、深度近似、延迟光栅实验，以及特定植被删面结果不作为通用优化接入。近景加速记录也不是所有视角的帧率保证。

## 验证与性能边界

新增测试覆盖快/慢分配、分配失败回退和释放归属、对齐/溢出、排序缓冲生命周期、直接映射缓存冲突、完整缓存与代次回绕、精确位置去重、独立三角形、重叠面排序、普通实例与现有物体管线的颜色/深度对照、拒绝模式、按行背景，以及连续帧零分配和释放无泄漏。原有图形与材质测试继续执行。

移植工程记录的 AC6 固定橡树近景为约 375.29 ms 渲染、13.16 ms 传屏，串口完成帧报告 2.5 FPS，SDRAM 12708232 字节。这些是历史板端数据，场景已为 480 草/54 树，与早期 384 草基线不同，不能跨场景计算整体提速比例。本次没有连接开发板、重新执行 ARMCC/ARMCLANG 或测量游戏 FPS，不能把这些数字写成本次合并的性能承诺。

本次主机验收：RGB888/16 位索引、RGB565/16 位索引（开启分桶/预验证/阶段计数）、RGB888/32 位索引（开启分桶）、RGB565 最小功能与自定义内存配置，各 30 项 CTest 通过，共 120 项；SDK 配置选择/不一致拒绝 20 项通过。新增路径的 AddressSanitizer/UBSan 5 项通过；当前运行环境的 ptrace 限制使 LeakSanitizer 无法工作，因此关闭其自动泄漏扫描，泄漏与帧内分配仍由测试分配计数器独立验收。另以复制后的头文件与真实静态库编译、运行独立 RGB888/16 位消费者，通过实例、缓存与释放检查；未重打发布包。

```sh
  -DYMGRE_BUILD_DEMOS=OFF -DYMGRE_BUILD_YMGUI_HOST=OFF \

cmake --build build/.cache/roam-port-check -j2
ctest --test-dir build/.cache/roam-port-check --output-on-failure
```
